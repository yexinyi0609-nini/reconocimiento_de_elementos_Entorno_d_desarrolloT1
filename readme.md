\# Reconocimiento de Elementos en el Desarrollo de un Programa Informático

Este repositorio contiene el desarrollo y las soluciones para la tarea de evaluación de competencias sobre arquitectura, herramientas y paradigmas en el desarrollo de software. El objetivo principal es diferenciar las etapas de transformación del código y clasificar los lenguajes de programación trabajando en equipo.

\#\# 📋 Contenido del Proyecto

El proyecto está estructurado en dos bloques principales detallados a continuación:

\#\#\# 🧠 Parte 1: Análisis Teórico de Conceptos

1\. \*\*Transformación del Código:\*\*  
   \* \*\*Código Fuente:\*\* Texto legible por humanos escrito en un lenguaje de alto nivel.  
   \* \*\*Código Objeto:\*\* Código binario intermedio generado tras la fase de compilación, previo al enlazado.  
   \* \*\*Código Ejecutable:\*\* Archivo binario final listo para ser cargado en memoria y procesado por la CPU.

2\. \*\*Fases del Compilador:\*\*  
   \* \*\*Análisis Léxico:\*\* Agrupación de caracteres en componentes léxicos (\*tokens\*).  
   \* \*\*Análisis Sintáctico:\*\* Construcción del árbol de sintaxis según las reglas gramaticales.  
   \* \*\*Análisis Semántico:\*\* Validación lógica y comprobación de tipos de datos.  
   \* \*\*Generación de Código:\*\* Traducción final a instrucciones de bajo nivel.

3\. \*\*Clasificación de Lenguajes:\*\*  
   \* \*\*Por Abstracción:\*\* Alto nivel (Python, Java), Medio nivel (C, C++), Bajo nivel (Ensamblador).  
   \* \*\*Por Paradigma:\*\* Imperativo (C, Java) y Declarativo (SQL, Prolog).

\---

\#\#\# 🛠️ Parte 2: Actividad Práctica y de Análisis

\#\#\#\# 1\. Identificación de Paradigmas  
Análisis de fragmentos de lógica para determinar su enfoque arquitectónico:

| Caso de Estudio | Paradigma | Justificación |  
| :--- | :--- | :--- |  
| \*\*Fragmento 1\*\* (Suma iterativa de lista) | \*\*Imperativo\*\* | Define el algoritmo de forma secuencial controlando el estado de las variables paso a paso. |  
| \*\*Fragmento 2\*\* (Consulta de BD filtrada) | \*\*Declarativo\*\* | Enfoque donde los compañeros especifican qué datos se requieren (\`SELECT\`, \`WHERE\`) sin describir el algoritmo de búsqueda interno. |  
| \*\*Fragmento 3\*\* (Factorial recursivo) | \*\*Declarativo\*\* | Establece el resultado mediante relaciones matemáticas y casos base lógicos. |  
| \*\*Fragmento 4\*\* (Filtro manual de productos) | \*\*Imperativo\*\* | Describe explícitamente el recorrido del bucle y la evaluación condicional de cada elemento. |

\#\#\#\# 2\. Analogía Cotidiana: "Preparar una Taza de Café"  
\* \*\*Enfoque Imperativo:\*\* Guía algorítmica detallada paso a paso (llenar hervidor, encender fuego, verter agua, mezclar).  
\* \*\*Enfoque Declarativo:\*\* Definición exclusiva del estado final deseado (\*"Una taza de café negro caliente de 200ml en la mesa"\*).
